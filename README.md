# mini-Trello

Каркас приложения для досок и карточек задач: Vue 3 + TypeScript + Vite на frontend и Node.js + NestJS на backend.

## Требования

- Node.js 24
- npm 11

Сборка и проверка типов проверены на Node.js 24.11.1 / npm 11.6.2; зависимости установлены через Node.js 24.18.0 / npm 11.16.0.

## Установка и запуск

Все команды выполняются из корня репозитория:

```sh
npm ci
npm run dev
```

В репозитории предусмотрен общий `package-lock.json` для обоих npm workspaces.

- Frontend: http://127.0.0.1:5173
- Backend: http://127.0.0.1:3000/health
- Ответ проверки: `{"status":"ok"}`

Стартовая страница проверяет backend через `/api/health`. Vite перенаправляет запрос на `/health` сервера NestJS. Для разработки CORS не требуется. Оба сервера слушают только локальный интерфейс. Остановка — Ctrl+C.

Можно запускать приложения отдельно в двух терминалах:

```sh
npm run dev -w frontend
npm run dev -w backend
```

## Проверки и сборка

```sh
npm run typecheck
npm run build
npm start
```

Сборка frontend находится в `frontend/dist`, backend — в `backend/dist`. `npm start` запускает собранный backend; предварительно остановите его режим разработки, чтобы освободить порт 3000.

Для просмотра собранного frontend: `npm run preview -w frontend`. Preview показывает статическую сборку; проверка API требует отдельной настройки прокси `/api` при размещении. Команда `npm run dev` уже содержит этот прокси.

## Структура и текущий объём

- `frontend/src` — стартовая страница и проверка соединения.
- `backend/src` — модуль NestJS и `GET /health`.

Доски, списки, карточки, база данных и авторизация пока не реализованы.

`npm audit` сообщает о двух связанных предупреждениях high: NestJS 11.2.8 использует `multer` 2.4.0. Исправление доступно в `multer` 2.5.0, но `npm audit fix` текущую зависимость не обновляет. Загрузка файлов в этом каркасе не реализована; перед её добавлением нужно устранить предупреждение и повторить аудит.
