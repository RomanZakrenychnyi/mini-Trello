# mini-Trello

[Открыть приложение →](https://mini-trello-rx64.onrender.com)

Доски проектов на Vue 3 + TypeScript + Vite, Node.js + NestJS и SQLite + Prisma 6.

## Установка и запуск

Требуются Node.js 24 и npm 11. Все команды выполняются из корня репозитория:

```sh
npm ci
npm run db:setup
npm run dev
```

- Frontend: http://127.0.0.1:5173
- Backend: http://127.0.0.1:3000
- Проверка сервера: http://127.0.0.1:3000/health

`db:setup` генерирует Prisma Client и применяет сохранённые миграции. Команда безопасна для повторного запуска: существующая база не очищается. База находится в `backend/prisma/dev.db`, создаётся автоматически и исключена из Git вместе с временными файлами SQLite. Для резервной копии остановите backend и скопируйте файл базы.

Vite перенаправляет `/api/*` на backend (без префикса `/api`). Оба сервера слушают только локальный интерфейс. Остановка — Ctrl+C. По отдельности их можно запускать в двух терминалах:

```sh
npm run dev -w frontend
npm run dev -w backend
```

## Доски

На главной странице доступны список досок и форма создания. Название содержит от 1 до 100 символов; пробелы по краям удаляются. После создания открывается страница `/boards/:id`. Можно вернуться к списку, обновить страницу и перезапустить сервер: доски сохраняются в SQLite. Одинаковые названия допустимы.

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | `/health` | `{ "status": "ok" }` |
| GET | `/boards` | Массив досок, новые первыми |
| POST | `/boards` | Создание, JSON `{ "name": "Мой проект" }`, ответ 201 |
| GET | `/boards/:id` | Доска или 404 |
| PATCH | `/boards/:id` | Переименование, JSON `{ "name": "Новый проект" }` |
| GET | `/boards/:id/deletion-preview` | Число списков и карточек: `{ "lists": 2, "cards": 5 }` |
| DELETE | `/boards/:id` | Удаление доски со всем содержимым, ответ `{ "id": "..." }` |

На странице доски доступны переименование и удаление. Перед удалением интерфейс загружает количество списков и карточек и предупреждает о невозможности восстановления. Удаление выполняется одной транзакцией (карточки → списки → доска); данные других досок сохраняются. После удаления открывается главная страница. Для несуществующей доски API возвращает 404, при конфликте параллельных изменений — 409 с возможностью повторить действие. Новые миграции не требуются.

Доска содержит `id`, `name`, `createdAt`, `updatedAt`. Некорректное название возвращает 400. Авторизация пока не реализована; все доски находятся в одном общем локальном пространстве.

## Списки внутри доски

На странице доски можно создать колонку, переименовать её и удалить после подтверждения. Название — от 1 до 100 символов после удаления пробелов по краям. Колонки сохраняются в порядке создания; изменение порядка перетаскиванием пока не реализовано. Списки каждой доски изолированы от других досок.

Список можно удалить только без карточек: интерфейс отключает кнопку, а база данных запрещает удаление непустого списка. API возвращает 409, если в списке есть карточки.

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | `/boards/:boardId/lists` | Списки доски по `position` |
| POST | `/boards/:boardId/lists` | Создание, JSON `{ "name": "В работе" }`, ответ 201 |
| PATCH | `/boards/:boardId/lists/:id` | Переименование, JSON `{ "name": "Готово" }` |
| DELETE | `/boards/:boardId/lists/:id` | Удаление пустого списка, ответ `{ "id": "..." }` |

Несуществующая доска при чтении/создании возвращает 404. Обращение к списку другой доски, переименование или удаление несуществующего списка возвращают 404. Некорректное название возвращает 400. На хостинге маршруты имеют префикс `/api`.

После обновления исходников локально выполните `npm run db:setup`: новая миграция добавляет таблицу списков и сохраняет существующие доски. Для PostgreSQL подготовлена отдельная миграция в `backend/prisma/postgres/migrations`; она применится при следующем одобренном деплое.

## Карточки задач

Внутри списка можно создавать карточки, редактировать название и описание, удалять после подтверждения. Название — от 1 до 200 символов после обрезки пробелов по краям, описание — до 5000 символов (необязательно, переносы строк сохраняются). Карточки можно перетаскивать за ручку «⠿» между местами вставки, включая пустой список. Кнопки ↑/↓ меняют порядок, выбор другого списка переносит карточку в его начало. Во время захвата копия карточки следует за указателем, исходное место остаётся полупрозрачным, а отпускание сопровождается короткой анимацией. Escape отменяет захват. Учитывается системная настройка уменьшения движения. Порядок сохраняется в базе; при ошибке интерфейс показывает сообщение и перечитывает данные сервера.

PATCH `/:id/move` относительно базового маршрута карточек принимает `{ "targetListId": "...", "position": 0 }`. Позиция — индекс с нуля в целевом списке после извлечения переносимой карточки; допустима вставка в конец. Ответ — перемещённая карточка. Перестановка обоих списков выполняется одной транзакцией. Целевой список другой доски и устаревший исходный список возвращают 404, неверная позиция — 400, конфликт параллельных изменений после повторных попыток — 409. Новая миграция для перемещения не нужна.

Базовый маршрут: `/boards/:boardId/lists/:listId/cards` (на хостинге с `/api`). GET возвращает массив карточек; POST принимает `{ "title": "Задача", "description": "Описание" }` и возвращает 201. PATCH `/:id` изменяет название и/или описание; DELETE `/:id` удаляет карточку и возвращает `{ "id": "..." }`. Обращения к чужому списку/доске возвращают 404, некорректные поля — 400. Пустое описание очищает его; пропущенное при PATCH поле остаётся прежним.

После обновления выполните `npm run db:setup`: миграция добавляет карточки без очистки досок и списков. Подготовлена также PostgreSQL-миграция для следующего одобренного деплоя.

## Поиск карточек

На странице доски поле поиска фильтрует карточки по подстроке в названии или описании сразу при вводе, без учёта регистра и пробелов по краям запроса. Счётчик показывает общее число совпадений во всех списках; при ошибке загрузки одного из списков сообщает о неполных результатах. Кнопка «Сбросить поиск» и Escape в поле поиска возвращают все карточки. Пустой запрос или одни пробелы не фильтруют доску.

Во время поиска отключены перетаскивание, кнопки изменения порядка и перенос в другой список. Скрытие карточек не меняет их порядок или данные, не влияет на запрет удаления непустого списка. Поиск работает по загруженным карточкам текущей доски; API и схема базы не изменяются.

## Проверки и сборка

```sh
npm run typecheck
npm run build
npm test
npm start
```

Тесты API создают отдельную временную SQLite-базу, проверяют валидацию, создание, чтение, 404, редактирование и удаление списков и карточек, ограничения длины полей, изоляцию досок и списков, запрет удаления непустого списка и сохранение порядка после перезапуска приложения. Рабочую базу тесты не меняют. `npm test` собирает backend: не запускайте его одновременно с backend watch или другой сборкой.

`npm start` запускает собранный backend; порт 3000 должен быть свободен. Артефакты: `frontend/dist` и `backend/dist`. Для просмотра frontend-сборки: `npm run preview -w frontend`. При размещении нужно настроить прокси `/api` к backend и возврат `index.html` для маршрутов frontend.

## Схема базы

- `backend/prisma/schema.prisma` — модель данных.
- `backend/prisma/migrations` — история миграций, хранится в Git.
- `npm run db:migrate:dev -w backend -- --name change_name` — создание новой миграции при изменении схемы.
- `npm run db:setup` — применение сохранённых миграций.

Backend поддерживает необязательную переменную `DATABASE_URL` для отдельной базы во время тестов; команды миграции по умолчанию работают с `backend/prisma/dev.db`.

## Размещение: Render Free + Neon Free

Для приложения выбран Render Free, для постоянного хранения досок — PostgreSQL в Neon Free. Render выключает бесплатный сервер после 15 минут простоя; первый запрос после паузы может занять около минуты. Локальная SQLite-база для хостинга не используется: файловая система бесплатного Render не сохраняет изменения при перезапусках.

`render.yaml` содержит конфигурацию бесплатного сервиса в Frankfurt. Автоматический деплой отключён: последующие публикации запускаются вручную. Актуальные ограничения: [Render Free](https://render.com/docs/free), [Neon Free](https://neon.com/pricing).

1. Создайте проект Neon на тарифе Free, желательно в регионе Frankfurt. Используйте отдельную пустую базу для mini-Trello.
2. В Render создайте Blueprint из этого GitHub-репозитория с конфигурацией `render.yaml`.
3. В секретную переменную `DATABASE_URL` в Render передайте строку подключения PostgreSQL из Neon с SSL. Не добавляйте её в Git, README или сообщения.
4. Проверьте, что выбран `Free`. Build: `npm ci --include=dev && npm run build:hosting`. Start: `npm run start:hosting`.
5. После публикации откройте выданный Render адрес, создайте доску, обновите страницу и проверьте `/api/health`.

На хостинге API доступен под `/api`, frontend — на том же домене; прямое открытие `/boards/:id` поддерживается. Сервер использует `PORT` хостинга и слушает `0.0.0.0`. PostgreSQL-модель и миграции находятся в `backend/prisma/postgres`. Миграции применяются при старте (в Free нет отдельного pre-deploy шага). Локальные команды продолжают генерировать SQLite-клиент; после `build:hosting` выполните `npm run db:setup`, прежде чем возвращаться к локальной разработке.

Локальные доски автоматически в Neon не переносятся. Размещённое приложение пока является общим демо без авторизации: любой посетитель видит и создаёт доски.

## Зависимости

Текущий `npm audit` сообщает о 6 предупреждениях high: цепочка NestJS → multer (2) и Prisma CLI → @prisma/config → deepmerge-ts / effect (4). Автоматическое исправление без перехода на другую основную версию Prisma не устраняет все предупреждения. Загрузка файлов не реализована; Prisma CLI используется локально для генерации и миграций. Перед внешним размещением следует обновить эти зависимости и повторить аудит.
