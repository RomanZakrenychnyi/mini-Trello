# mini-Trello

Доски проектов на Vue 3 + TypeScript + Vite, Node.js + NestJS и SQLite + Prisma 6.

## Установка и запуск

Требуются Node.js 24 и npm 11. Все команды выполняются из корня репозитория:

```sh
npm ci
npm run db:setup
npm run dev
```

- Frontend: http://127.0.0.1:5173
- Backend: http://127.0.0.1:3000
- Проверка сервера: http://127.0.0.1:3000/health

`db:setup` генерирует Prisma Client и применяет сохранённые миграции. Команда безопасна для повторного запуска: существующая база не очищается. База находится в `backend/prisma/dev.db`, создаётся автоматически и исключена из Git вместе с временными файлами SQLite. Для резервной копии остановите backend и скопируйте файл базы.

Vite перенаправляет `/api/*` на backend (без префикса `/api`). Оба сервера слушают только локальный интерфейс. Остановка — Ctrl+C. По отдельности их можно запускать в двух терминалах:

```sh
npm run dev -w frontend
npm run dev -w backend
```

## Доски

На главной странице доступны список досок и форма создания. Название содержит от 1 до 100 символов; пробелы по краям удаляются. После создания открывается страница `/boards/:id`. Можно вернуться к списку, обновить страницу и перезапустить сервер: доски сохраняются в SQLite. Одинаковые названия допустимы.

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | `/health` | `{ "status": "ok" }` |
| GET | `/boards` | Массив досок, новые первыми |
| POST | `/boards` | Создание, JSON `{ "name": "Мой проект" }`, ответ 201 |
| GET | `/boards/:id` | Доска или 404 |

Доска содержит `id`, `name`, `createdAt`, `updatedAt`. Некорректное название возвращает 400. Списки, карточки и авторизация пока не реализованы; все доски находятся в одном общем локальном пространстве.

## Проверки и сборка

```sh
npm run typecheck
npm run build
npm test
npm start
```

Тесты API создают отдельную временную SQLite-базу, проверяют валидацию, создание, чтение, 404 и сохранение после перезапуска приложения. Рабочую базу тесты не меняют. `npm test` собирает backend: не запускайте его одновременно с backend watch или другой сборкой.

`npm start` запускает собранный backend; порт 3000 должен быть свободен. Артефакты: `frontend/dist` и `backend/dist`. Для просмотра frontend-сборки: `npm run preview -w frontend`. При размещении нужно настроить прокси `/api` к backend и возврат `index.html` для маршрутов frontend.

## Схема базы

- `backend/prisma/schema.prisma` — модель данных.
- `backend/prisma/migrations` — история миграций, хранится в Git.
- `npm run db:migrate:dev -w backend -- --name change_name` — создание новой миграции при изменении схемы.
- `npm run db:setup` — применение сохранённых миграций.

Backend поддерживает необязательную переменную `DATABASE_URL` для отдельной базы во время тестов; команды миграции по умолчанию работают с `backend/prisma/dev.db`.

## Зависимости

Текущий `npm audit` сообщает о 6 предупреждениях high: цепочка NestJS → multer (2) и Prisma CLI → @prisma/config → deepmerge-ts / effect (4). Автоматическое исправление без перехода на другую основную версию Prisma не устраняет все предупреждения. Загрузка файлов не реализована; Prisma CLI используется локально для генерации и миграций. Перед внешним размещением следует обновить эти зависимости и повторить аудит.
